# 兵損グラフ仕様

## 目的

戦闘シミュレーション結果を数値表だけでなく、**各ターンでどれだけ兵力を失ったか / 残ったかを直感的に見られるグラフ**として表示する。

ユーザーが一目で以下を判断できることを目標にする。

- どのターンで大きく兵損したか
- 自軍と敵軍のどちらが先に崩れたか
- 回復によってどこで持ち直したか
- どの武将が兵損の原因/被害の中心だったか
- 同じ編成でも複数回シミュレーション時にどの程度ブレるか

---

# 1. 基本の兵損グラフ

シミュレーション結果画面に、折りたたみ詳細とは別に**主要グラフとして表示**する。

## デフォルト表示

折れ線グラフ。

X軸:
- 開戦時
- 1T
- 2T
- 3T
- ...
- 8T

Y軸:
- 残存兵力

系列:
- 自軍合計兵力
- 敵軍合計兵力

例:

```text
兵力
30000 | 自軍 ────────╲
      |               ╲
20000 |                ╲___
      |      敵軍 ──╲
10000 |             ╲____
      |
    0 +--------------------
       開戦 1T 2T 3T ...
```

---

# 2. 表示モード切替

グラフ上部に切替を置く。

- `残存兵力`
- `ターン別兵損`
- `累計兵損`
- `武将別`

## 残存兵力

各ターン終了時の残兵。

## ターン別兵損

棒グラフまたはエリア/バー相当で、各ターンに失った兵数を表示。

例:

```text
1T  自軍 -1200 / 敵軍 -1800
2T  自軍 -3200 / 敵軍 -900
3T  自軍 -700  / 敵軍 -4100
```

回復が入る場合、`純減少` と `被ダメージ総量` を混同しない。

最低限以下を別データとして保持する。

- damageTaken
- healingReceived
- netTroopChange

---

# 3. 武将別兵力線

詳細モードで6武将それぞれの残兵を表示できる。

- 自軍武将1
- 自軍武将2
- 自軍武将3
- 敵軍武将1
- 敵軍武将2
- 敵軍武将3

ただし6本すべて常時表示すると見づらいため、初期状態では非表示または選択式にする。

### UI

武将画像 + 名前をタップして系列ON/OFF。

例:

`[黒田画像] 黒田官兵衛 ☑`
`[秀吉画像] 豊臣秀吉 ☑`
`[ねね画像] ねね ☐`

---

# 4. 戦法イベントとの連動

グラフだけでは「なぜここで兵損したか」が分からないため、ターン点をタップ/ホバーした時にイベント概要を表示する。

例:

```text
3ターン目

自軍兵損: 4,210
敵軍兵損: 1,840

主なイベント
- 北条氏康「相模の獅子」発動
- 柿崎景家「越後二天」 2,180ダメージ
- 黒田官兵衛 1,420回復
```

PCはhover + click。
スマホはtap。

長い戦闘ログ全文は別のログ画面で表示する。

---

# 5. ダメージ / 回復の分離

兵損グラフ用データでは以下を必ず分ける。

```ts
interface TurnUnitSnapshot {
  turn: number
  side: "ally" | "enemy"
  generalId: string
  troopsStart: number
  damageTaken: number
  healingReceived: number
  troopsEnd: number
}
```

部隊合計も集計できるようにする。

```ts
interface TurnArmySnapshot {
  turn: number
  allyTroops: number
  enemyTroops: number
  allyDamageTaken: number
  enemyDamageTaken: number
  allyHealing: number
  enemyHealing: number
}
```

`残兵差だけ見てダメージ量とみなす` 実装は禁止。

# 6. 100回 / 1000回シミュレーション

複数回試行時は1本のランダム戦闘だけを表示するのではなく、統計表示を用意する。

最低限:

- 平均残存兵力
- 中央値
- 25〜75%範囲
- 平均ターン別兵損

グラフの基本線は平均値。

可能なら帯表示で分布範囲を出す。

例:

`平均線 + 25〜75%レンジ`

ただしMVPで帯表示が重い場合は、平均線のみ実装し、分布は後続フェーズでもよい。

---

# 7. 比較モード

保存したシミュレーション結果同士を比較できる土台を作る。

例:

- 編成A vs 北条テンプレ
- 編成B vs 北条テンプレ

比較指標:
- 平均残兵
- 平均兵損
- 勝率
- 平均戦闘ターン

初期MVPでは必須ではないが、データschemaは将来比較しやすい形にする。

---

# 8. グラフの見やすさ

重要:

- 最初から情報を詰め込みすぎない
- PC/スマホ対応
- 凡例は武将画像/名前と連動
- 自軍/敵軍を一貫して識別できるデザイン
- ダークモードでも見える
- ターンラベルを省略しすぎない
- 値はツールチップで正確に確認できる

画面が狭い場合は横スクロールではなく、レスポンシブ縮小または詳細モード切替を優先。

---

# 9. 戦闘ログとの同期

将来的に、グラフのターン点を押すと戦闘ログがそのターンへ自動スクロールするようにする。

逆に戦闘ログのイベントを押すと、そのイベントが発生したターンのグラフ点を強調できる設計が望ましい。

---

# 10. 保存

シミュレーション結果を保存する場合、再計算なしでグラフを再表示できるよう、snapshotを保存可能にする。

```ts
interface SavedSimulationResult {
  id: string
  formationAId?: string
  formationBId?: string
  seed?: string
  repetitions: number
  resultSummary: unknown
  turnSnapshots: TurnArmySnapshot[]
  unitSnapshots?: TurnUnitSnapshot[]
  createdAt: string
}
```

大量保存時の容量対策として、1000戦すべての生ログは保存せず、集計済みsnapshot + 必要な代表戦闘のみ保存する方式を検討する。

# 11. Acceptance Criteria

- [ ] 1回シミュレーションで自軍/敵軍の残存兵力をターン別折れ線で表示
- [ ] 開戦時〜最大8Tまで表示
- [ ] ターン別兵損表示へ切替可能
- [ ] ダメージと回復を別集計
- [ ] 武将別表示を選択式で切替可能
- [ ] PC hover / スマホ tap でターン詳細を確認可能
- [ ] グラフから主要戦法イベントを確認可能
- [ ] 100/1000回時は平均推移を表示
- [ ] グラフがスマホ画面で破綻しない
- [ ] 保存済みシミュ結果から再表示可能なschema
